# Правила модели v0.2.0

## Входные данные

Варианты принимаются из VCF, VCF.GZ или TSV. В фенотипе используются HPO ID и вручную проверенный набор синонимов из `knowledge.json`. Нераспознанный фенотип не заменяется моделью по догадке.

## Веса

Итоговая шкала:
```
score = 0.55 * phenotype + 0.35 * molecular + 0.10 * inheritance
```

Каждый компонент лежит в диапазоне 0–1. Итог переводится в формат 0–100 только для удобства отображения, не в процент вероятности.

## Защита от переинтерпретации

- VUS и конфликтующие ClinVar интерпретации не дают молекулярной поддержки.
- Benign/likely benign не дают молекулярной поддержки.
- Raw pathogenic/likely pathogenic label сам по себе также не засчитывается: требуется allele-condition-transcript совпадение и приемлемый review status.
- Consequence (например, missense) не является самостоятельным доказательством патогенности.
- Совпадение гена и наличие ALT-генотипа показываются как наблюдение, а не как доказательство причинности.
- Недостающие данные и отсутствие кандидата имеют разные статусы.

## Проверка

Unit-тесты проверяют чтение VCF, распознавание HPO ID, неучёт VUS и статус incomplete. GitHub Actions запускает тесты при push и pull request. Успешный CI не заменяет внешнюю научную валидацию, калибровку или клиническое исследование.
