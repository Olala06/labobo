# Геномный детектив

Локальный исследовательский прототип для приоритизации генетических гипотез по вариантам и фенотипу. Поддерживает отдельный VCF/VCF.GZ/TSV, ZIP-архив с вариантами и фенотипическим файлом, а также текстовый ввод фенотипа в веб-интерфейсе или CLI.

Проект вдохновлён архитектурой [Synth_Hack / Genomic Detective](https://github.com/NursuUwU/Synth_Hack), но реализован как самостоятельный компактный Python-проект. Внешних Python-зависимостей нет; по умолчанию все действия работают локально и офлайн. По явному флагу `--online` доступна аннотация вариантов через Ensembl VEP с локальным SQLite-кэшем.

## Публикация сайта в интернете (Render)

В репозитории есть `render.yaml` для развёртывания на Render. Он создаёт Python Web Service, использует порт платформы, проверку `/healthz` и автоматически генерирует пароль для доступа к приложению. Сервис привязан к ветке `main`; после подключения репозитория Render может автоматически публиковать новые коммиты.

### Однократная настройка

1. Создайте аккаунт на [Render](https://render.com/) и войдите в Dashboard.
2. Подключите GitHub в настройках Render и разрешите доступ к репозиторию **Olala06/labobo**. Репозиторий сейчас приватный; Render может развернуть приватный репозиторий после подключения Git-провайдера.
3. В Render выберите **New → Blueprint**, затем укажите репозиторий `Olala06/labobo` и подтвердите создание сервиса из `render.yaml`.
4. Дождитесь успешного Deploy. Render выдаст адресу сервиса вид `https://имя-сервиса.onrender.com`.
5. В Dashboard откройте сервис → **Environment**. Имя пользователя — `admin`; скопируйте сгенерированное значение `APP_PASSWORD` и сохраните его в менеджере паролей. При открытии сайта браузер запросит логин и пароль.

После первой настройки каждый новый commit в `main` может запускать автоматическое развёртывание. Приложение слушает `0.0.0.0:$PORT`, а публичные страницы и загрузка файлов защищены HTTP Basic авторизацией. Render завершает TLS для внешнего HTTPS-подключения.

### Бесплатный тариф и данные

На бесплатном Render Web Service приложение может засыпать после периода бездействия (15 минут); следующий запрос запускает его снова. Файловая система бесплатного сервиса временная, а локальные файлы теряются при перезапуске/засыпании/redeploy. Поэтому веб-интерфейс обрабатывает загруженные данные в памяти и не сохраняет файлы и отчёты в постоянное хранилище. Это демонстрационное размещение, не production-среда для клинических данных.

**Не загружайте реальные идентифицируемые геномные/медицинские данные на публичный хостинг без правового основания, согласия, проверки условий обработки данных провайдером и отдельной оценки безопасности.** Пароль защищает доступ к сайту, но не превращает бесплатный хостинг в сертифицированную медицинскую инфраструктуру.

Документация: [первое развёртывание Render](https://render.com/docs/your-first-deploy), [Web Services](https://render.com/docs/web-services), [ограничения бесплатного тарифа](https://render.com/docs/free), [секреты и переменные окружения](https://render.com/docs/blueprint-spec).

## Что делает прототип

1. Читает варианты из VCF/VCF.GZ или TSV; извлекает ген, последствие, ClinVar-поле и генотип, если эти сведения присутствуют во входе.
2. По явному флагу `--online` может дополнительно получить VEP consequence/transcript-аннотацию и закэшировать ответ.
3. Сопоставляет фенотип с небольшой явно курируемой таблицей терминов HPO и с HPO ID, указанными в тексте/файле.
4. Запускает три детерминированных экспертных модуля: фенотипический, молекулярный и наследования.
5. Объединяет результаты по весам из `config/ranking.json`, ранжирует состояния и формирует объяснение по каждому экспертному модулю.
6. Сохраняет HTML, Markdown, JSON и TSV-отчёты.

Это не три автономных LLM-агента. Оркестратор, правила и веса реализованы кодом. LLM в текущей версии не подключена. Тексты объяснений формируются из результатов экспертных модулей, а не создаются генеративной моделью.

## Версия правил и ограничения

Текущая версия прототипа — **0.2.0**. Веса по умолчанию: 0.55 фенотип, 0.35 молекулярные данные, 0.10 наследование. Их можно менять в `config/ranking.json`; сумма должна равняться 1.

**Баллы не являются вероятностью заболевания, клинической точностью или классификацией ACMG/AMP.** Это внутренняя эвристическая шкала ранжирования. В этой демонстрационной версии молекулярный эксперт показывает варианты и аннотации, но **не добавляет молекулярный балл**: одного совпадения гена, последствия варианта или текстового `CLNSIG` недостаточно. Для положительной молекулярной поддержки нужна проверка точного ALT-аллеля, конкретного заболевания, транскрипта и статуса рецензирования ClinVar. Такая курируемая allele-condition-transcript база пока не включена.

VUS, conflicting interpretations и benign/likely benign не добавляют положительную молекулярную поддержку. Отсутствие записи или данных не трактуется как доброкачественность. Для AD/AR показывается только ограниченная совместимость генотипа; VCF сам по себе не доказывает de novo, сегрегацию, cis/trans-фазу или причинность.

База `knowledge.json` намеренно маленькая и включает только демонстрационные профили синдрома Марфана и муковисцидоза. Это не полный импорт HPO, ClinVar или GeneReviews. Не заявляются результаты внешней валидации или клиническая точность. Не используйте систему для диагностики, лечения или решений о репродуктивном риске. Не загружайте идентифицируемые генетические данные в недоверенные среды.

## Быстрый запуск

### Windows — запуск одним двойным щелчком

1. На GitHub нажмите **Code → Download ZIP**.
2. В Проводнике Windows нажмите правой кнопкой по ZIP и выберите **Извлечь всё…**. Не запускайте файлы прямо внутри ZIP.
3. Откройте извлечённую папку и дважды нажмите **`Start.cmd`** (не `README.md` и не `start.ps1`).
4. При первом запуске программа проверит Python. Если его нет, она автоматически скачает официальный переносимый Python 3.14.10 с python.org, проверит архив по SHA-256 и поместит интерпретатор внутрь папки проекта `.runtime/`. Затем откроет приложение в браузере.
5. При следующих запусках Python уже будет в папке проекта, поэтому повторная загрузка не нужна.

Устанавливать Python в Windows, менять PATH, запускать `pip install` или иметь права администратора не требуется. Для первой загрузки нужен интернет (официальный архив около 12 МБ) и Windows PowerShell. Запускатель поддерживает Windows x64, ARM64 и 32-bit. Если автоматическая загрузка не удалась, окно покажет конкретную ошибку; проверьте интернет/антивирус или установите Python вручную с [python.org](https://www.python.org/downloads/windows/).

Механизм такой же, как у [Synth_Hack](https://github.com/NursuUwU/Synth_Hack): короткий `Start.cmd` вызывает `start.ps1`, общий `scripts/python-runtime.ps1` находит или подготавливает Python, а `run.ps1` запускает пакет в изолированном режиме с явным путём к папке проекта. Сам ZIP переносимого Python по умолчанию не хранится в Git-репозитории: он загружается с официального сайта при первом запуске и проверяется по SHA-256.

### macOS / Linux

Требуется установленный Python **3.10+**. В терминале из распакованной папки выполните:

```sh
sh start.sh
```

Или запустите CLI напрямую:

```sh
python3 -m genomic_detective serve --open
```

### Адрес и остановка

По умолчанию интерфейс доступен только на локальном компьютере: **http://127.0.0.1:8765**. Остановка — `Ctrl+C` в терминале. Можно выбрать другой порт:

```sh
python -m genomic_detective serve --port 8766 --open
```

## Работа с интерфейсом

В веб-форме выберите `.vcf`, `.vcf.gz`, `.tsv` или `.zip`, добавьте описание фенотипа и нажмите **Проанализировать**. ZIP может включать файл вариантов и файл фенотипов с именем, содержащим `phenotype`, `phenotypes` или `hpo`. Текстовый ввод фенотипа объединяется с фенотипами из архива.

Для распознавания фенотипа можно вводить известные словарю названия (сейчас доступны русские и английские синонимы из `knowledge.json`) или HPO ID, например `HP:0001166`. Неизвестные формулировки не превращаются в выдуманные термины: интерфейс покажет, что признаки не распознаны.

## Команды

Проверить локальную базу и входные данные:

```powershell
.\run.ps1 prepare
.\run.ps1 prepare --dataset examples\demo_case.vcf
```

Проанализировать VCF с фенотипом:

```powershell
.\run.ps1 run --dataset examples\demo_case.vcf --phenotype "HP:0001166 HP:0001083 HP:0002616 HP:0000098" --output outputs\demo
```

Запустить локальный веб-интерфейс:

```powershell
.\run.ps1 serve --open
```

## Необязательная онлайн-аннотация Ensembl VEP

По умолчанию приложение не делает сетевых запросов. Чтобы получить consequence/transcript-аннотации, явно включите `--online` и подтвердите сборку входных координат:

```powershell
.\\run.ps1 prepare --dataset examples\\demo_case.vcf --online --assembly GRCh38
.\\run.ps1 run --dataset examples\\demo_case.vcf --phenotype "HP:0001166 HP:0001083 HP:0002616 HP:0000098" --online --assembly GRCh38 --output outputs\\vep_demo
```

Поддерживается только явно указанная сборка **GRCh38**. Запросы отправляются пакетами до 200 записей и кэшируются локально в `data/ensembl-vep.sqlite`. В Ensembl передаются только координаты/аллели вариантов; текст фенотипа и идентификаторы пациента не отправляются. Геномные координаты могут быть чувствительными данными — включайте эту функцию только при наличии разрешения. VEP-аннотация последствия не доказывает патогенность и сама по себе не добавляет молекулярный балл. Подробности формата: [Ensembl VEP REST API](https://rest.ensembl.org/documentation/info/vep_region_post).

На macOS/Linux или при использовании Python напрямую:

```sh
python -m genomic_detective prepare --dataset examples/demo_case.vcf
python -m genomic_detective run --dataset examples/demo_case.vcf --phenotype "HP:0001166 HP:0001083 HP:0002616 HP:0000098" --output outputs/demo
python -m genomic_detective serve --open
```

Оценка top-1 выполняется только по предоставленным ожидаемым ответам (это не клиническая валидация):

```sh
python -m genomic_detective evaluate --reports outputs/demo --expected examples/expected_answers.json --output outputs/demo/evaluation.json
```

Для проверки кода:

```sh
python -m unittest discover -s tests -v
# Windows PowerShell: .\validate.ps1
# macOS/Linux: sh validate.sh
```

Коды возврата: **0** — команда завершилась; **2** — вход/случай неполный или не было строк для оценки; **1** — ошибка выполнения/файла.

## Входные данные

### VCF / VCF.GZ

Читаются стандартные колонки VCF. Для поиска гена предпочтительны поля `INFO/SYMBOL` или `INFO/GENE`; также поддерживается извлечение части аннотаций из `INFO/CSQ` (если в заголовке определён формат) и `INFO/ANN`. Из FORMAT/sample извлекается GT. ClinVar-поле читается из `CLNSIG` / `CLIN_SIG`, но само по себе не засчитывается как молекулярное доказательство.

### TSV

Имена колонок сопоставляются без учёта регистра. Поддерживаемые синонимы: `chrom/chr/chromosome`, `pos/position/start`, `ref/reference`, `alt/alternate`, `gene/symbol/genesymbol`, `consequence/effect/annotation`, `clinvar/clinical_significance/clnsig`, `genotype/gt`.

### ZIP и фенотипы

ZIP читается в памяти, без распаковки файлов по путям на диске. Фенотипы могут задаваться текстовым полем интерфейса или файлом, имя которого содержит `phenotype`, `phenotypes` либо `hpo`. Для сопоставления используются только термины из локальной базы и HPO ID.

## Результаты

В выбранной папке `outputs`:

- `case_XX.html` — отчёт для просмотра в браузере.
- `case_XX.md` — текстовый объяснимый отчёт.
- `case_XX.json` — входные данные, распознанные фенотипы, экспертные баллы, кандидаты, источники, предупреждения и ограничения.
- `case_XX_ranking.tsv` — рейтинг для конкретного случая.
- `ranking.tsv` — общий рейтинг всех обработанных случаев.
- `predictions.tsv` — ответы только для завершённых случаев.
- `predictions.partial.tsv` — случаи с неполными входными данными.
- `run.json` — состав запуска, статусы и неполные случаи.
- `evaluation.json` — появляется после отдельной команды `evaluate`.

Наличие рейтинга не означает, что данные полны. Статусы `incomplete` и `no_convincing_candidate` имеют разный смысл: неполные данные нельзя интерпретировать как отсутствие подходящего кандидата.

## Архитектура

```text
VCF / VCF.GZ / TSV / ZIP + фенотип
                 |
          dataset.py (парсер)
                 |
       knowledge.py (словарь)
                 |
        pipeline.py (оркестратор)
          /          |           \
 phenotype expert  molecular   inheritance
          \          |           /
             ranking.py
                 |
     reporting.py: HTML / MD / JSON / TSV
                 |
          evaluation.py
```

- `genomic_detective/dataset.py` — чтение VCF, TSV, ZIP и фенотипов.
- `genomic_detective/annotations.py` — опциональная VEP-аннотация и SQLite-кэш.
- `genomic_detective/experts.py` — три детерминированных экспертных модуля.
- `genomic_detective/ranking.py` — взвешенная приоритизация и статусы.
- `genomic_detective/pipeline.py` — оркестрация анализа.
- `genomic_detective/reporting.py` — объяснимые HTML/Markdown/JSON/TSV отчёты.
- `genomic_detective/web.py` — локальный веб-интерфейс на стандартной библиотеке Python.
- `genomic_detective/cli.py` — команды подготовки, анализа, оценки и запуска сервера.
- `config/ranking.json` — веса и порог внутренней оценки.

## Источники и дальнейшее развитие

Курируемые карточки заболеваний содержат ссылки на GeneReviews, HPO и поисковые страницы PubMed/ClinVar. Поисковые ссылки ведут к живой выдаче базы, а не к заранее проверенной статье по конкретному варианту. Точные доказательства по аллелю должны быть добавлены в отдельную рецензируемую базу с идентификаторами источников и версиями данных.

Следующий этап для научно более строгой версии: полные HPO disease profiles; фиксация версии Ensembl VEP и метаданных ответа в отчётах; точное ClinVar allele-condition-transcript сопоставление с review status; отдельные правила для de novo, сегрегации и фазировки; независимый development/test набор и проверка калибровки до отображения вероятностей.
